# Phase 4.6 Fanout ACK Follow-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the remaining per-publish cross-Shard scheduling overhead and 64-KiB output tail latency while preserving QoS 1 scheduled-PUBACK semantics, Message Store ACK barriers, Lease ownership and zero-allocation enqueue paths.

**Architecture:** Each Event Loop Shard gets one persistent bounded Fanout Scheduler that consumes pooled Batch entries in FIFO order. QoS 1 ACK still occurs after all target Shard Batches are accepted; Message Store mode remains a completion barrier. Large single-segment PUBLISH payloads are evaluated through a separate PipeWriter path that avoids generic segmented packet copying.

**Tech Stack:** .NET 10, MQTT 5, Kestrel, `System.IO.Pipelines`, `ArrayPool<T>`, `ConcurrentQueue<T>`, xUnit v3, Microsoft Testing Platform, PowerShell 7.

**Spec:** `perf/baseline/broker-phase4.6-2026-11-25.md`; `docs/sharded-actor-broker-plan.md`.

## Global Constraints

- Keep public Broker, ASP.NET Core, management and Dashboard APIs unchanged.
- Performance clients use MQTTnet Client only.
- Maximum benchmark subscriber count is `500`.
- Three-run medians must reach throughput `>= 1.00x` MQTTnet and p99 `<= 1.00x` MQTTnet before merge.
- Message Store success remains a QoS 1 PUBACK and QoS 2 PUBREC barrier.
- QoS 2 PUBREL/PUBCOMP semantics remain unchanged in this plan.
- Publish Interceptors run before ACK; Enqueue Interceptors and Delivery Observers may run after scheduled ACK.
- A Batch is acknowledged only after it enters a bounded target-Shard queue.
- Every queued or Inflight message must retain the shared `MqttZeroMessageLease` independently.
- Steady-state scheduled enqueue, signal, route, queue and encoding paths must remain `0 B/op`.
- Do not add fixed sleeps, increase benchmark drain timeouts or delete failing cells.
- C# files use CRLF, one top-level type per file, forced braces and XML documentation on public API.
- Every task ends with its focused tests, allocation sentinel, `dotnet format --verify-no-changes` and an independent commit.
- Do not merge `master` or start Phase 5 while any acceptance gate is red.

```csharp
private static async Task BlockShardAsync(
    MqttZeroEventLoop shard,
    TaskCompletionSource started,
    TaskCompletionSource release,
    CancellationToken cancellationToken)
{
    await shard.EnqueueAsync(
        new BlockingShardWork(started, release),
        cancellationToken);
    await started.Task.WaitAsync(cancellationToken);
}

private sealed class BlockingShardWork : MqttZeroShardWork
{
    private readonly TaskCompletionSource _release;
    private readonly TaskCompletionSource _started;

    public BlockingShardWork(
        TaskCompletionSource started,
        TaskCompletionSource release)
    {
        _started = started;
        _release = release;
    }

    public override async ValueTask ExecuteAsync(
        MqttZeroEventLoop shard,
        CancellationToken cancellationToken)
    {
        _started.TrySetResult();
        await _release.Task.WaitAsync(cancellationToken);
    }
}
```

```csharp
internal sealed class MqttZeroFanoutScheduler : IAsyncDisposable
{
    private const int MaximumEntriesPerPass = 64;

    private readonly MqttZeroEventLoop _shard;
    private readonly ConcurrentQueue<MqttZeroFanoutScheduledBatch> _ready;
    private readonly SemaphoreSlim _capacity;
    private readonly MqttZeroFanoutSchedulerWork _work;
    private int _scheduled;
    private int _stopping;

    internal MqttZeroFanoutScheduler(
        MqttZeroEventLoop shard,
        int queueCapacity,
        MqttZeroFanoutDiagnostics? diagnostics)
    {
        _shard = shard;
        _capacity = new SemaphoreSlim(
            queueCapacity,
            queueCapacity);
        _ready = new ConcurrentQueue<MqttZeroFanoutScheduledBatch>();
        _work = new MqttZeroFanoutSchedulerWork(this);
    }

    internal ValueTask EnqueueAsync(
        MqttZeroFanoutOperation operation,
        int shardId,
        CancellationToken cancellationToken)
    {
        return EnqueueCoreAsync(operation, shardId, cancellationToken);
    }
}
```

The implementation must:

- Wait on `_capacity` before accepting a Batch.
- Rent one `MqttZeroFanoutScheduledBatch`.
- Enqueue in FIFO order.
- Schedule one reusable `MqttZeroFanoutSchedulerWork`.
- Process at most 64 entries per pass.
- Yield after 250 microseconds so inbound connection work is not starved.
- Release the queue entry after `ExecuteBatchAsync`.
- Call `CompleteBatch()` exactly once for every accepted entry.
- Return the queue entry to its pool.
- Release `_capacity` after execution or failure.
- Drain accepted entries during normal Stop before stopping the Shard.

```csharp
private static IReadOnlyList<MqttZeroQueuedMessage> CreateLargeBatch(
    MqttZeroBufferPool pool,
    int messageCount,
    int payloadSize)
{
    MqttZeroMessageLease lease = MqttZeroMessageLease.CopyFrom(
        new ReadOnlySequence<byte>("large/topic"u8.ToArray()),
        ReadOnlySequence<byte>.Empty,
        new ReadOnlySequence<byte>(new byte[payloadSize]),
        MqttQualityOfServiceLevel.AtLeastOnce,
        false,
        null,
        null,
        pool);
    try
    {
        List<MqttZeroQueuedMessage> messages = new(messageCount);
        for (int index = 0; index < messageCount; index++)
        {
            MqttZeroQueuedMessage message =
                MqttZeroQueuedMessage.Rent(
                    lease,
                    MqttQualityOfServiceLevel.AtLeastOnce,
                    false,
                    null,
                    null);
            message.PacketIdentifier = checked((ushort)(index + 1));
            messages.Add(message);
        }

        return messages;
    }
    finally
    {
        lease.Release();
    }
}

private static void ReleaseBatch(
    IReadOnlyList<MqttZeroQueuedMessage> batch)
{
    for (int index = 0; index < batch.Count; index++)
    {
        batch[index].Release();
    }
}
```

```csharp
internal async ValueTask<int> WriteLargePublishBatchAsync(
    IReadOnlyList<MqttZeroQueuedMessage> messages,
    CancellationToken cancellationToken)
{
    int encodedBytes = 0;
    for (int index = 0; index < messages.Count; index++)
    {
        MqttZeroQueuedMessage message = messages[index];
        MqttZeroPublishView view = CreatePublishView(message);
        MqttZeroPublishPacketBuffer buffer =
            MqttPublishPacketCodec.EncodeHeader(
                view,
                _bufferWriter);
        WriteHeader(buffer.Header);
        await WritePayloadAsync(
            buffer.Payload,
            cancellationToken).ConfigureAwait(false);
        encodedBytes += buffer.Length;
    }

    return encodedBytes;
}
```
