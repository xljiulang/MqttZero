# MQTTZero 与 MQTTnet 吞吐对比（raw 客户端，2026-11-27）

## 结论

- 换成仓库内置的 raw 压测客户端后，三格吞吐对比为 `0.981`、`0.998`、`0.909`：
  QoS 0 两格基本持平，QoS 1 / 100 / 64 KiB 仍落后 9%。
- 同一台机器、同一天、同样三个格子，用 MQTTnet 客户端测得的比值是 `1.040`、
  `1.029`、`0.896`。换客户端后三个比值全部向 1 收敛，说明 MQTTnet 客户端
  侧的解析与分配放大了两个 broker 的差距，之前的“两格领先”不是 broker 优势。
- raw 客户端下 MQTTZero 的交付 p99 全面更低：`0.504`、`0.692`、`0.385`。
  发布调用 p99 为 `1.090`、`1.052`、`0.812`，只有 QoS 1 / 100 / 64 KiB 更好。
- 三格 `compare` 门禁全部未通过（要求吞吐比 > 1 且发布 p99 比 < 1）。

## 为什么换客户端

同一 broker 下，单纯把压测客户端从 MQTTnet 换成 raw 就能把吞吐提高
1.7–2.6 倍：

| 单元格 | MQTTZero（MQTTnet 客户端） | MQTTZero（raw 客户端） | 提升 |
|---|---:|---:|---:|
| QoS 0 / 1 / 32 B | 6,940.82 | 11,896.25 | 1.71× |
| QoS 0 / 100 / 8 KiB | 324.50 | 354.95 | 1.09× |
| QoS 1 / 100 / 64 KiB | 47.57 | 122.14 | 2.57× |

MQTTnet 客户端在每个 64 KiB 消息上都会复制一次 payload，并对 100 条订阅流
分别解析，压测端因此成为瓶颈。raw 客户端是 benchmark-only 的最小 MQTT 5
实现，两个 broker 共用同一实现，所以换客户端只改变压测端，不改变对比公平性。

## 环境与命令

- Windows `10.0.26300`，.NET `10.0.15`，8 个逻辑处理器（i7-8565U，4 核 8 线程）
- Server GC、并发 GC、分层 PGO；Shard 与 Kestrel I/O 队列均解析为 8
- 压测客户端：`--client raw`（benchmark-only），单连接发布
- 预热 5 秒、测量 20 秒、3 轮，取中位数；`--max-pending 1024`
- 提交：`1964eb0`

```powershell
dotnet benchmarks/MqttZero.BrokerBenchmarks/bin/Release/net10.0/MqttZero.BrokerBenchmarks.dll compare `
  --client raw --qos <0|1> --subscribers <n> --payload <bytes> `
  --warmup 5 --seconds 20 --repetitions 3 --max-pending 1024 `
  --output artifacts/compare-target/2026-11-27-raw-<cell>.json
```

raw 客户端不支持 QoS 2，因此三点矩阵只覆盖 QoS 0 与 QoS 1；QoS 2 仍以
MQTTnet 客户端的结果为准。

|---|---:|---:|---:|---:|---:|---:|
| QoS 0 / 1 / 32 B | 6,940.82 | 11,896.25 | 6,674.82 | 12,129.34 | 1.040 | 0.981 |

读法：换客户端后 MQTTZero 与 MQTTnet 的吞吐差距缩小到 0–9%，而不是
MQTTnet 客户端下的 −10% 到 +4%。两个 broker 都能从更轻的客户端获益，
但 MQTTZero 在 64 KiB QoS 1 上获益更多（2.57× 对 2.53×），比值因此略微回升。

## 限制

- raw 客户端是仓库内为基准测试编写的最小实现，不是独立第三方产品；它能排除
  MQTTnet 客户端自身的开销，但不能替代第三方压测工具的交叉验证。本机当前
  没有可用的 `emqtt_bench`、`mqtt-benchmark`、`mosquitto_pub` 或 paho。
- QoS 2 无法用 raw 客户端覆盖，因为该客户端只实现 QoS 0/1。
- QoS 0 / 1 / 32 B 的交付 p99 逐轮离散（613 / 11,108 / 1,268 µs），中位数
  1268 µs 只作记录，不能单独用于判定。
- 这是单机单次 3 轮采样。结论限定为“同日同机、raw 客户端、三点矩阵”。
