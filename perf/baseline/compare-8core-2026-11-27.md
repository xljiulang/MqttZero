# MQTTZero 与 MQTTnet 复测（8 核，2026-11-27）

## 结论

- 三格同机交替对比：QoS 0 / 1 / 32 B 与 QoS 0 / 100 / 8 KiB 的端到端吞吐略高于
  MQTTnet（`1.040x`、`1.029x`），QoS 1 / 100 / 64 KiB 落后（`0.896x`）。
- 落后格的交付 p99 优于 MQTTnet（`0.739x`），发布调用 p99 更差（`1.142x`）。
  MQTTnet 在该格三轮回测中每轮都有 13–42 ms 的排空积压，MQTTZero 全部为 0 ms。
- **不能与 `compare-8core-2026-11-26.md` 的绝对值直接比较**：MQTTnet 自身三格的
  吞吐在两日之间分别变化 −16%、+23%、+46%，环境漂移大于两者差距。本记录只提供
  同日同机的比值。
- 本次补齐了旧记录缺失的交付延迟来源：`DeliveryLatencyP50/P95/P99/MaxMicroseconds`
  已写入结果 JSON，可从原始文件逐轮复现。2026-11-26 的 JSON 不含这些字段，
  旧报告中的“交付 p99”无法从存档复现。

## 环境

- Windows `10.0.26300`，.NET `10.0.15`，8 个逻辑处理器（i7-8565U，4 核 8 线程）
- Server GC、并发 GC、分层 PGO
- 自动 Shard 数与 Kestrel I/O 队列数均解析为 8
- 客户端：MQTTnet 5.2.0，进程内单连接发布
- 预热 5 秒、测量 20 秒、3 轮，取中位数
- 提交：`47cce98`（含已合并的 shard-owned egress 与 0.12 公开面调整）

命令：

```powershell
dotnet benchmarks/MqttZero.BrokerBenchmarks/bin/Release/net10.0/MqttZero.BrokerBenchmarks.dll compare `
  --client mqttnet --qos <qos> --subscribers <n> --payload <bytes> `
  --warmup 5 --seconds 20 --repetitions 3 --max-pending 1024 `
  --output artifacts/compare-target/2026-11-27-<cell>.json
```

吞吐为 3 轮中位数，延迟为 3 轮中位数。

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| QoS 0 / 1 / 32 B | 6,940.82 | 6,674.82 | 1.040 | 311 / 337 | 0.923 | 983 / 1,161 | 0.847 | 69.8 / 51.7 | 0.0 / 0.0 |
| QoS 0 / 100 / 8 KiB | 324.50 | 315.39 | 1.029 | 533 / 939 | 0.568 | 35,345 / 38,171 | 0.926 | 103.0 / 120.1 | 34.7 / 2.6 |

三格均为 `failed=0`、`missing=0`、`duplicate=0`。

替代口径：本表吞吐取 `EndToEndThroughputPerSecond`；三格 `drain/(measure+drain)`
最大为 `QoS 0 / 100 / 8 KiB` 的 0.0017，远低于 `0.10` 的切换阈值，因此端到端口径
与前一轮判定规则一致，无需改用 publish-window。

逐轮离散度很大：QoS 1 / 100 / 64 KiB 上 MQTTZero 的第 2 轮吞吐 42.93、发布 p99
100 ms，与另两轮（47.57、52.08）不在同一分布；该格中位数不能当作稳定水平。
这台机器（4 核 8 线程低压 CPU）只能支撑“同日同机、量级可比”的结论，不支持
跨日期或跨机器的绝对值比较。

## 门槛判定

- QoS 0 / 1 / 32 B：`compare` 门禁通过（吞吐比 > 1，发布 p99 比 < 1）。
- QoS 0 / 100 / 8 KiB：门禁通过。
- QoS 1 / 100 / 64 KiB：门禁失败，原因是吞吐比 0.896 小于 1 且发布 p99 比 1.142
  大于 1。严格门禁（吞吐 > 1 且发布 p99 < 1）在 2026-11-26、2026-11-27 两次
  复测中均未通过该格。

## 与 2026-11-26 复测的关系

| 单元格 | 11-26 吞吐比 | 11-27 吞吐比 | MQTTnet 绝对值变化 |
|---|---:|---:|---:|
| QoS 0 / 1 / 32 B | 0.973 | 1.040 | 7,992 → 6,675（−16%） |
| QoS 0 / 100 / 8 KiB | 0.866 | 1.029 | 257 → 315（+23%） |
| QoS 1 / 100 / 64 KiB | 0.865 | 0.896 | 36.4 → 53.1（+46%） |

MQTTnet 侧代码未变，其绝对值却在两天之间变化 16%–46%，说明本机环境噪声
（后台负载、频率、NUMA/超线程调度）是主导变量。两次复测的比值只能各自作为
当日证据：11-26 三格全部落后，11-27 两格领先、一格落后。两次都未达到
“三个复测轮次稳定领先”的性能声明门槛，因此不构成对 MQTTnet 的普遍优势声明。

MQTTZero 侧在这两天之间合入了 shard-owned egress 与 0.12 公开面调整，但该格
的对比对象是同一台机器上的 MQTTnet，不能把差异单独归因于这些提交。
