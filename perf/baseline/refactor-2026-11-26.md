## 与计划的偏差

- 订阅/退订的筛选查找没有引入字符串键字典，而是收敛为 broker 内的
  `IndexOfSubscription` 线性扫描：SUBSCRIBE 包的过滤器数量远小于会话订阅数，
  线性扫描避免了每请求一次 UTF-8 转字符串分配。`BuildSubscriptionDiff` 仍使用
  原有的字符串索引。
- `eng/compare-broker-ab.ps1` 的 `Build-BenchmarkAssembly` 会把 `dotnet
  restore/build` 的输出混入函数返回值，导致 `dotnet $driverAssembly` 收到数组；
  已改为 `Out-Host`。该修复随 `fb8803b` 一起提交（提交信息未单独列出）。
- 若本机改用 `MqttZeroPersistentHashMap` 以外的新键类型，需保持 `where TKey :
  notnull` 约束（本轮用它替代了 4 处 `key!`）。

## 第二轮：删除线格式转发方法（`refactor/wire-format-forwarders`）

第一轮把实现收敛进 `MqttZeroWireFormat` 后，仍有 15 个方法只是
`return MqttZeroWireFormat.X(...)`。第二轮把这些转发全部删除，调用点改为显式写
`MqttZeroWireFormat.` 前缀：

| 文件 | 删除 |
|---|---|
| `Mqtt5PropertyReader` | `TryReadUInt16`、`TryReadVariableByteInteger`、`TrySkipBinary` |
| `MqttPacketCodec.Helpers` | 同名 3 个 + `WriteVariableByteInteger(Span,int)` + `GetVariableByteIntegerSize` |
| `MqttPublishPacketCodec` | 同名 3 个 + `WriteVariableByteInteger(Span,int)` + `GetVariableByteIntegerSize` |
| `Mqtt5PropertyWriter` | `GetVariableByteIntegerSize` |
| `MqttZeroClientConnection` | `GetVariableByteIntegerSize`（已无调用点的死代码） |
| `MqttZeroPacketWriter` | `WriteVariableByteInteger(Span<byte>, uint)`；实例方法保留，内部改调 `int` 实现 |

新加的源码规则测试立即多抓到一个计划外的转发：`Mqtt5PropertyReader.TrySkipUtf8`
（无调用点，已删除）。合计删除 16 个转发方法。

保留：`WriteVariableByteInteger(IBufferWriter<byte>, uint)` 适配器（做 GetSpan/Advance）、
`IsValidPublishTopic`（类型转换）、`MqttZeroConnectedClient.GetSnapshot`（公开 API 入口）。

测试侧：`MqttZeroPacketWriterTests` 里与 `MqttZeroWireFormatTests` 完全重复的 7 个
边界用例删除；`SourceConventionTests` 新增 `NoMethodForwardsToSharedWireHelpers`
与内联自检用例。

验证：Release 构建 0 警告 0 错误；`MqttZero.Tests` 729/729；`MqttZero.Dashboard.Tests`
24/24；`MqttZero.BrokerBenchmarks.Tests` 69/69；`dotnet format --verify-no-changes`
通过；覆盖率四包 PASS（MqttZero 89.06%/78.13%，MqttZero.Server 86.47%/77.5%）。
覆盖率脚本首次运行报告 2 例失败（未保留用例名，均为计时敏感用例），同一命令与脚本
